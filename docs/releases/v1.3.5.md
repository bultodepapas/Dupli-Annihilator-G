# Dupli-Annihilator-G v1.3.5

## Executive Summary

`v1.3.5` is a targeted reliability patch. It resolves a critical issue introduced in `v1.3.4` where the installed Windows application failed to launch silently after installation. No engine behavior, UI, or API changes are included.

---

## Critical Fix: Desktop Application Fails to Launch on Windows

### Root Cause

The `apps/desktop/src-tauri/Cargo.lock` file was excluded from version control via `.gitignore`. As a result, each CI release build resolved the Tauri 2.x Rust dependency tree independently — whatever was newest on crates.io at build time. Between the `v1.3.3` and `v1.3.4` CI runs, a Tauri 2.x crate update introduced a regression that caused the Windows application to crash silently at startup.

The crash was invisible to the end user because the release binary uses `windows_subsystem = "windows"`, which suppresses the console window — and therefore any panic output — in production builds.

### Fix Applied

- **`apps/desktop/src-tauri/Cargo.lock` added to version control.**
  The lockfile is now committed and tracked. All Tauri 2.x Rust dependencies are pinned to the exact versions validated at release time.

- **`pin-desktop-lockfile` maintenance workflow added.**
  A new `workflow_dispatch` action (`pin-desktop-lockfile.yml`) generates a fresh `Cargo.lock` using the stable Rust toolchain and commits it to `main`. This workflow is the designated mechanism for intentional dependency upgrades going forward.

- **Pinned dependency baseline for this release:**
  - `tauri` → `2.10.3`
  - `tauri-plugin-updater` → `2.10.0`
  - `tauri-plugin-dialog` → `2.6.0`
  - `tauri-plugin-process` → `2.3.1`
