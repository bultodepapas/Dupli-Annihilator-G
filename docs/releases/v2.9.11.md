## Executive Summary

`v2.9.11` fixes the desktop `RUNNING` focus mode layout so the execution surface no longer appears clipped on shorter desktop windows.

The running state now uses a denser composition: the output path, frozen-output config, cancel actions, and telemetry remain visible together without introducing scrollbars or hiding data.

---

## Fix: Running Focus Mode Density

### What changed

- Reorganized the focused output panel into a compact two-row layout.
- Reduced vertical spacing in the running header, output surface, and telemetry dock.
- Added height-based desktop breakpoints for the running shell at `900px` and `820px`.
- Hardened the focus containers with `min-height: 0` and start-aligned grid behavior to prevent silent clipping.

### Why it matters

Before this patch, the running focus mode could exceed the available viewport height even though the app shell is intentionally locked to `100vh`. That made the lower part of the focused output panel feel cut off while the telemetry dock remained visible.

With this release:

- `Cancel` remains visible and prioritized,
- the output path and frozen config stay readable,
- the separator preview is still present,
- the telemetry dock stays on screen,
- the desktop runtime view preserves the intended no-scroll focus experience.
