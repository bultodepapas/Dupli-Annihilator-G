# Dupli-Annihilator-G v2.9.4

## Executive Summary

`v2.9.4` publishes the rich-input startup and extraction improvements prepared in `v2.9.3`, with a corrected release version/tag alignment so the desktop release workflow can complete successfully.

There are no functional changes relative to the intended `v2.9.3` payload. This release exists to ship the verified extraction-progress and EPUB-performance improvements under a clean semver tag.

---

## Feature: Visible Extraction Telemetry

Jobs that begin with `EPUB` or `PDF` extraction now show useful progress immediately instead of appearing idle.

### What changed

- the telemetry footer shows extraction progress before tokenization starts,
- extraction reports the current rich-file index and total rich files,
- the current input path is shown while a file is being extracted,
- the frontend polls once immediately after `start_job` so the first visible state arrives sooner.

### Why it matters

Large rich-input jobs no longer sit at `0/0` files and `0` tokens while preprocessing is doing real work in the background.

---

## Improvement: Faster EPUB Extraction

The EPUB text extraction path was optimized to reduce overhead before deduplication begins.

### What changed

- chapter text is streamed into a buffered writer,
- HTML/XML tag stripping is performed in a single pass,
- common entities such as `&amp;`, `&nbsp;`, `&lt;`, `&gt;`, `&quot;`, and `&apos;` are decoded inline,
- cancellation checks happen between EPUB chapters/resources.

### Why it matters

This reduces allocation and copying overhead when many EPUBs are loaded at once and improves cancellation responsiveness during extraction.

---

## Improvement: Better AUTO Mode Choice For Rich Inputs

`AUTO` mode now resolves rich inputs first and chooses between `RAM` and `DISK` using the extracted-text footprint rather than the compressed container size.

### Why it matters

Large EPUB collections are less likely to be routed into an overly optimistic `RAM` execution path.

---

## Compatibility

- **No breaking desktop workflow changes.**
- **No output format changes.**
- Existing deduplication behavior is preserved; this release improves observability, extraction performance, and AUTO-mode selection accuracy for rich inputs.
