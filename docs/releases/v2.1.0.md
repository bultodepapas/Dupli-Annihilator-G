# Dupli-Annihilator-G v2.1.0

## Executive Summary

`v2.1.0` introduces the **Word Search** feature — a built-in word checker that lets users load a wordlist and instantly verify whether a specific word exists within it. This is exposed in the desktop UI and the backend API.

---

## New Feature: Word Search (Word Checker)

### What It Does

Users can now load any text-based wordlist into the application and search for individual words to check if they exist in that list. This is useful for verifying cleaned datasets, checking membership in large dictionaries, or validating entries against a reference file.

### How It Works

1. **Load a wordlist** — Select a text file via the file picker. The file is parsed using the same high-performance tokenizer used for deduplication (`LossyLineReader` + `TokenIter`), and all unique tokens are stored in a fast hash set (`HashSet` with `ahash`).
2. **Search for a word** — Type any word and click **Check**. The lookup is O(1) using the loaded hash set.
3. **See the result** — The UI displays **FOUND** or **NOT FOUND** with the total word count of the loaded wordlist.

### Technical Details

| Component | Change |
|---|---|
| `dedupe_core::WordChecker` | New module — loads wordlist files into `HashSet<Box<str>, RandomState>`, exposes `contains()`, `len()`, `is_empty()` |
| `dedupe_backend` | Two new public methods: `load_wordlist_for_checker(path)` → `LoadCheckerResponse`, `check_word(word)` → `CheckWordResponse` |
| Tauri commands | `load_wordlist_for_checker` and `check_word` registered as IPC commands |
| Desktop UI | New `WordCheckerPanel` component with file picker, load button, word input, and result display |
| Localization | All 10 language files updated with Word Checker UI strings |

### Performance

- Wordlist loading uses the same optimized pipeline as the deduplication engine (BOM stripping, lossy UTF-8, fast hashing).
- Word lookup is O(1) — instant regardless of wordlist size.
- Memory usage is proportional to the number of unique tokens in the loaded wordlist.
