# Dupli-Annihilator-G v2.4.0

## Executive Summary

`v2.4.0` adds an **optional word-length filter** that drops tokens by character count before deduplication. Users can specify a `[min, max]` range (1–10) to erase all tokens whose length falls within that range. This is useful for cleaning datasets by removing short noise tokens (1-letter, 2-letter, 3-letter words, etc.).

---

## New Feature: Word-Length Filter

### Problem

Many text datasets contain short noise tokens — single characters, two-letter fragments, abbreviations — that pollute the output. Previously, users had to post-process the deduplicated file to remove them.

### Solution

Two new optional parameters: `drop_length_min` and `drop_length_max`. When both are set, any token whose character count falls within `[min, max]` is silently dropped before deduplication. The valid range for both values is 1–10.

**CLI usage:**
```bash
dedupe-cli -i input.txt -o output.txt --drop-length-min 1 --drop-length-max 3
```
This drops all tokens that are 1, 2, or 3 characters long.

**Desktop UI:** The feature is available via the API. When not specified, both fields default to `None` and the filter is inactive (backward compatible).

### Examples

| Input tokens | `--drop-length-min 1 --drop-length-max 2` | Result |
| --- | --- | --- |
| `a, bb, ccc, dddd` | drops `a`, `bb` | `ccc, dddd` |
| `hi, hello, world, ok` | drops `hi`, `ok` | `hello, world` |

## Detailed Changes

### Core Engine (`crates/core/`)

- **`config.rs`**: Added `drop_length_min: Option<usize>` and `drop_length_max: Option<usize>` to `Config`. Added validation (range 1–10, min ≤ max). Added `should_drop_by_length()` helper method.
- **`stats.rs`**: Added `filtered_by_length: u64` counter to `Stats`.
- **`engine.rs`**: Length filter check in RAM deduplication path (after trim/drop_empty, before hash insertion).
- **`disk.rs`**: Length filter check in disk bucket partitioning path.
- **`disk_sort.rs`**: Length filter check in external merge sort run-generation path.

### Job Runner (`crates/job_runner/`)

- **`lib.rs`**: Added `filtered_by_length` to `StatsSnapshot`. Added `drop_length_min` and `drop_length_max` to `RunSummary`.

### Backend API (`crates/backend/`)

- **`lib.rs`**: Added `drop_length_min` and `drop_length_max` to `StartJobConfig` with `#[serde(default)]`. Wired through to core `Config`.

### CLI (`apps/cli/`)

- **`main.rs`**: Added `--drop-length-min` and `--drop-length-max` CLI arguments. Done output now includes `filtered_by_length` count.

### Tests

- **`engine_smoke.rs`**: Updated `Config` construction with new fields.
- **`job_runner_smoke.rs`**: Updated `Config` construction with new fields.
- **`backend_smoke.rs`**: Updated `StartJobConfig` construction with new fields.

## Compatibility

- **No breaking changes.** Both new fields default to `None` (filter inactive).
- Existing CLI invocations, desktop UI, and API consumers work without modification.
- The feature activates only when both `drop_length_min` and `drop_length_max` are explicitly set.
