# Dupli-Annihilator-G v1.3.6

## Executive Summary

`v1.3.6` fixes a startup crash that prevented the application from launching on Windows. The crash was introduced by a breaking change in `tauri-plugin-updater` 2.10.0 and was invisible to the user because the release binary suppresses the console window.

---

## Critical Fix: Application Crashes at Launch (Windows)

### Root Cause

`tauri-plugin-updater` 2.10.0 introduced a stricter initialization requirement: the plugin now panics at startup if its configuration section (`plugins.updater`) is absent or `null` in `tauri.conf.json`, even when the in-app updater is not actively used.

The CI build script (`configure-updater.mjs`) was written for the previous plugin behavior — when the updater signing keys are not configured, it omitted the `plugins.updater` section entirely. Under the old plugin version this was harmless. Under 2.10.0 the app panics immediately on launch with:

```
failed to run tauri app: PluginInitialization("updater",
"Error deserializing 'plugins.updater' within your Tauri configuration:
invalid type: null, expected struct Config")
```

Because the release binary uses `windows_subsystem = "windows"`, this panic produces no visible error — the application simply never opens.

### Fix Applied

`configure-updater.mjs` now always writes a `plugins.updater` entry. When the updater is not configured (no signing keys), it writes `{ "active": false }` instead of omitting the section. This satisfies the plugin's deserialization requirement while keeping all update functionality disabled.

| Area | Change |
|---|---|
| Deduplication engine | No change |

| CLI | No change |
| Windows launch | **Fixed** — startup crash resolved |
